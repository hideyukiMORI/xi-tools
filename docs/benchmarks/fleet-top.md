## 2026-09-02 — 作る前の試作（設計を決めた計測）

環境: WSL2（Linux 6.18・20 論理コア）・`gh` 2.x 認証済み・回線は家庭用。
対象: ローカル 60 リポ（`/home/xi/docker` 直下）・GitHub 60 リポ（archived 除く。うち 42 リポの部分集合でも計測）。
計測器: スクラッチパッドの使い捨て Rust（`std::thread::scope` ＋ `Mutex<VecDeque>` のワーカープールでサブプロセスを起動）。
リポには入れていない。壁時計は `Instant` / `/usr/bin/time`。**各行は 1 回の実行**（複数回あるものは `/` で並記）。

### GitHub — REST（`gh api` 1 本 = 1 エンドポイント。リポ × 3 本）

| 形 | 本数 | 壁時計 |
| --- | --- | --- |
| 直列 | 21（7 リポ） | 15.46 s（0.74 s/本。126 本に外挿すると 93 s） |
| 8 並列 | 126（42 リポ） | 10.72 s |
| 16 並列 | 126 | 6.31 s |
| 32 並列 | 126 | 3.53 s |
| 48 並列 | 126 | 2.84 s |
| 64 並列 | 126 | 2.38 s |

rate limit の消費: 126 点／回（core 5,000 点/時）。secondary rate limit には当たらなかった。
`gh` 自体の起動 0.28 s/回（`gh --version` × 5 = 1.42 s）。`curl` 単体 0.42 s に対し `gh api` 0.67 s。

### GitHub — GraphQL（1 リクエストに複数リポをエイリアスで並べる）

| 形 | 壁時計 |
| --- | --- |
| 1 本に 42 リポ（既定枝の CI・open PR・枝一覧つき） | 8.87 s |
| 1 本に 60 リポ | HTTP 502 |
| 1 本に 42 リポ、枝一覧を外す | 5.74 / 5.87 s |
| 42 リポを 7 リポ × 6 本で並列 | 1.66 / 2.40 / 1.76 / 2.00 s |
| 42 リポを 3 リポ × 14 本 | 1.60 s |
| 42 リポを 14 リポ × 3 本 | 2.25 s |
| 42 リポを 21 リポ × 2 本 | 3.15 s |
| **60 リポを 3 リポ × 20 本** | **1.35 / 1.49 / 1.45 s** |
| 60 リポを 6 リポ × 10 本 | 2.69 / 1.92 / 1.76 / 1.72 / 1.96 s |
| 60 リポを 10 リポ × 6 本 | 2.02 s |

rate limit の消費: 1 リクエスト = 1 点（GraphQL は REST と別枠の 5,000 点/時）。60 リポで 20 点。

### ローカル（`git status --porcelain=v2 --branch` / `worktree list` / `for-each-ref`。60 リポ × 3 本 = 180）

| 形 | 壁時計 |
| --- | --- |
| 直列 | 1.26 s（初回）/ 0.30 s（キャッシュ後） |
| 8 / 16 / 32 並列 | 0.05 / 0.03〜0.05 / 0.05〜0.08 s |

### 結論

3 リポ × N 本の GraphQL を並列に投げる形が最速で、60 リポが 1.4〜1.5 秒。`REPOS_PER_QUERY = 3` はこの表から決めた。
REST 64 並列（2.38 s・126 点）より速く、rate limit の消費は 1/6。
