## 1. 直す 3 点（実ファイル計測の 18 件が根拠。順に）

### 1-a. 複数行にまたがるフロー記法（14 件）

```yaml
healthcheck:
  test:
    [
      "CMD-SHELL",
      "curl -f http://localhost/ || exit 1"
    ]
  other: ["CMD", "mysqladmin", "ping",
          "-p${PASSWORD}"]
```

- `[` / `{` で始まる値が行内で閉じないとき、**閉じるまでの各行を「同じパスのスカラー行」として持つ**（ブロックスカラーと同じ形）。
  `key:` の次の行にインデントして `[` が来る形（今は「複数行にまたがるスカラー」エラー）も同じ
- 括弧の深さとクォート（`'…'` `"…"` の中の `]` `}` `#`）を跨線で追う。既存の `scan_flow` を行を跨いで使える形にする
- 各行の `value` は**その行の原文**（行頭の空白を除く）。`column` は一致の先頭
- 閉じないまま EOF・閉じないまま親より浅いインデントの行が来た → `Unsupported(MultiLineFlow)` は**廃止せず、「閉じていない」場合のエラーとして残す**（名前は実態に合わせて直してよい。設計メモの表の文言と一致させる）
- フロー記法の行の後ろの `# comment` は行末コメントとして扱う（`--comments` の対象）。フローの**中**の `#`（クォート外）は YAML では空白の後ならコメントだが、v1.1 では**中には入らない**方針なので、行末コメントの判定は「括弧の外」に限る。中の `#` は値の一部として持つ。doc コメントにこの割り切りを書く

### 1-b. タグ（3 件）

```yaml
environment: !override
  POSTGRES_DB: x
ports: !reset []
name: !!str 123
- !override
  - '18080:80'
```

- 値の先頭が `!` のとき、**タグ token（次の空白まで）を読み飛ばし**、残りを通常の値として読む。残りが空なら「空の値」と同じ（次の行の入れ子を受ける）
- `UnsupportedSyntax::Tag` は**廃止**（variant を消す。RS-002 で `match` が網羅なので消し漏れはコンパイラが落とす）
- タグ名は値ではないので検索に当たらない。設計メモに明記済み

### 1-c. `- { $ref: '#/x' }` のバグ（1 件）

```yaml
parameters:
  - { $ref: '#/components/parameters/IdPath' }
```

- シーケンス要素の先頭が `[` / `{` / `"` / `'` のときは **`key: value` の始まりとして扱わず、スカラー（フロー／クォート）として読む**。
  今は `{ $ref` をキーと誤読して `TrailingContent` にしている
- 同じ誤読がマッピングの値側にも無いか確認する（`key: { a: 1 }` は通っているはず。テストで固定）
