## 実測でわかったこと

`nene-recall` の ADR 0010 が「Go に無い」と記録した4点を Rust で測り直した。**全部あった。**

| NENE-PIXEL の規則 | Go | Rust（実測） |
| --- | --- | --- |
| KOT-002 不正状態を表現不能に・網羅性 | 無い | **ある**（`E0004`） |
| KOT-003 公開状態は不変 | 無い | **ある**（`let` が既定で不変） |
| KOT-004 `null` は一意の意味 | 不十分 | **ある**（`null` もゼロ値も無い＝`E0381`） |
| KOT-007 private コンストラクタ＋唯一のファクトリ | 不十分 | **ある**（`E0603`） |

さらに Rust には先行3事例のどれにも無いものがあった。

```
#![forbid(clippy::unwrap_used)]
#[expect(clippy::unwrap_used, reason = "テストだから")]
→ error[E0453]: expect(...) incompatible with previous forbid
```

**抑制しようとする行為そのものがコンパイルエラーになる。**
Kotlin の `@Suppress` にも Go の `//nolint` にもこれに相当するものは無い。

## 今日の判断

### 1. 抑制を二段構えにした

| 段 | 水準 | 抑制 |
| --- | --- | --- |
| 1段目 | `forbid` | **不可能**。例外を申請する窓口が存在しない |
| 2段目 | `deny` | `#[expect(lint, reason = "<規則 ID>: <理由>")]` **のみ** |

### 2. NENE-PIXEL の waiver 台帳を移植しなかった

**Rust では制度の大半をコンパイラが執行している。** forbid 層は申請窓口が無く、
deny 層の `#[expect]` は理由が必須で、不要になれば `unfulfilled_lint_expectations` が落とす。
台帳は「機械が見ていない抑制を人手で追う」ための仕組みで、**その対象がここには無い。**

⇒ 移植すると、機械が既に守っているものを人手で二重に追う形になる。却下理由は ADR に記録。

### 3. ADR の位置づけを CLAUDE.md と整理した

CLAUDE.md は「ADR 形式は取らない」と書いていたが、あれは**ツールの設計判断**についての規約。
**ゲートの判断はそれとは別の対象**で、QLT-005（ゲートを弱める変更は ADR を要する）が
定める以上、置き場が要る。⇒ 設計は `docs/design/`、ゲートは `docs/adr/`。CLAUDE.md に追記。

⚠️ **この分割は施主の未確認事項。** 異論があれば ADR 0001 を `docs/design/` 側へ畳む。

## 見つけた欠陥3件

### 1. `cognitive_complexity` が死んだ設定だった

`clippy.toml` に閾値を書いていたが、この lint は `nursery` 群にあり
`clippy::all` にも `pedantic` にも入らない。**一度も評価されていなかった。**

🔑 **設定ファイルに項目が在ることは、検査が効いていることの証明ではない。**
本物のコードだけを見ていたら永久に緑のままだった。

### 2. 検査器が自分自身を検出した

`xtask` を初めて repo に走らせたら違反7件。**全て検査器自身の検出語**だった。
ファイル単位の除外で黙らせると**そのファイルだけ他の CNF も効かなくなる**ので、
検出語を `concat!` で分割する形にした。**検査器は自分自身も検査対象である。**

### 3. 機械が判定できない条件を規約に書いていた

RS-003 を当初「**不変条件を持つ型に** `Default` を実装しない」と書いたが、
不変条件の有無は機械が判定できない。
**判定できない条件を規約に書くと、その規則は永久に planned のままになる。**
`Default` の全面禁止に変えて active にした。
